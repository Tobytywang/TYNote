   185 | ## 工作流与分支保护
   186 | 
   187 | ### 整体流程
   188 | 
   189 | ```
   190 | master(源码) --push/PR--> GitHub Actions 构建 --> gh-pages(产物) --> pages-build-deployment --> Pages 站点
   191 | ```
   192 | 
   193 | 1. 修改源码 → 合并到 `master`
   194 | 2. 触发 Action「Build and Deploy Jekyll Site」自动构建
   195 | 3. 构建产物写入 `gh-pages` 分支
   196 | 4. 平台自动执行 `pages-build-deployment` 发布到 GitHub Pages
   197 | 
   198 | ### 分支角色
   199 | 
   200 | | 分支 | 角色 | 维护方式 |
   201 | |------|------|----------|
   202 | | `master` | 唯一源码分支 | 人工维护，仅通过 PR 合并 |
   203 | | `gh-pages` | 构建产物分支 | 自动维护，CI 强制重建，禁止手动推送 |
   204 | 
   205 | ### 分支保护规则（已配置）
   206 | 
   207 | - **`master`**：要求 PR 审查，禁止直接 push
   208 | - **`gh-pages`**：要求 PR 审查；force push 例外仅授予 `github-actions[bot]`，保证自动部署不被拦截
